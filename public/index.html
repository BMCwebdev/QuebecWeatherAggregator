        Reading this data

        Each hour has an outdoor comfort score (0–100) derived from rain, feels-like temperature, humidity, wind gusts, and thunderstorm agreement across models. Continuous favorable blocks matter more than scattered single hours. Where model agreement is low, the models have not converged — treat those values as uncertain. The scoring formula is documented in llms.txt.

        Hourly consensus

        Scores prioritize continuous outdoor windows, thunderstorm agreement, heat index, wind gusts, and rain spread across models. Expand a “models” cell to see each model side by side.

          For AI agents

          Preferred path: fetch the server-rendered JSON below. It is computed by the site's Worker (which queries the models server-side), so it works even when your sandbox blocks external weather APIs or cannot run JavaScript. All endpoints are same-origin, need no key, and send Access-Control-Allow-Origin: *. The links follow the location and dates currently shown on this page.

          • /forecast/index.json — small index: decision summary, per-day rollups, and links to per-day files.
          • /forecast.json — full run: decision summary, per-day rollups, and every daytime hour with consensus, model spread (min/max/median), and the best_match blend.
          • /forecast/YYYY-MM-DD.json — one day with the full per-model breakdown; .summary.json for the smaller version.
          • Any location: add ?city=Burlington, VT or ?lat=…&lon=…, and optionally &start=YYYY-MM-DD&end=YYYY-MM-DD. Defaults are Québec, today and tomorrow.
          • /llms.txt — protocol doc: schema, field meanings, scoring formula, and how model agreement is defined.

          If you are running this page in a browser instead, the same payload is at window.__WEATHER_FORECAST__ and in the <script id="forecastData"> tag, or use “Export JSON”.
